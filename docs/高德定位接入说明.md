# 高德 Android 定位与地点搜索 SDK 接入

食刻 Android 端使用高德原生定位 SDK 6.5.1 与搜索 SDK 9.7.0，通过 Kotlin 模块连接 React Native。定位、地址解析和附近地点搜索共用 Android 平台 Key，不需要 Web 端或 Web 服务 Key。

## Key 与签名

- Android Key 配置：`android/gradle.properties` 的 `AMAP_API_KEY`；也可通过同名环境变量覆盖。
- 包名：`cn.shike.app`。
- 当前体验包签名 SHA1：`5E:8F:16:06:2E:A3:CD:2C:4A:0D:54:78:76:BA:A6:F3:8C:AB:F6:25`。
- Key 通过 Gradle Manifest placeholder 写入 `com.amap.api.v2.apikey`，不在 JS 中拼接 HTTP API。

## 代码入口

1. `android/app/build.gradle`：固定依赖 `com.amap.api:location:6.5.1` 与 `com.amap.api:search:9.7.0`。搜索 9.7.1 与当前定位版本有重复类，不能直接混用。
2. `android/app/src/main/AndroidManifest.xml`：Key、APSService 和前台定位 / 网络 / Wi-Fi 权限。
3. `AmapLocationModule.kt`：高精度单次定位、地址解析、禁用位置缓存、超时与取消释放。
4. `AmapLocationPackage.kt`、`MainApplication.kt`：惰性注册 React Native 原生模块。
5. `src/services/location.js`：高德说明、同意记录、运行时权限、取消信号和服务调用。
6. `src/domain/location.js`：结果格式转换；保留来源与坐标系。
7. `AmapPoiModule.kt`：附近 2 公里、每页 20 条地点查询，超时、取消与过期回调隔离。
8. `src/components/LocationPicker.js`：地点列表、关键词搜索、单选与确认；`MealEditor.js` 保留最终餐次保存流程。
9. `src/domain/places.js`：过滤无效地点、去重及保存选中地点的坐标、名称与地址。

## 调用流程

用户点击同级“位置”入口 → 打开选择弹窗 → 首次说明并同意 → 系统前台定位权限 → 高德 SDK 获取新位置 → 查询附近地点 → 用户可搜索并选中 → 确认后附加到该餐次。拍摄流程仍需最终确认保存记录。

列表包含当前位置作为备选，但不默认选中。选择商户时保存商户自身的坐标、POI ID、名称和地址；关闭不修改已有地点，不附加可清空地点。花费与评分保持不变。

位置服务同意版本为 2，包含定位与地点搜索说明；旧版本同意需重新确认。定位 SDK 与搜索 SDK 均在用户同意后声明隐私状态。关键词查询防抖 400ms，新请求、关闭及离开前台会使旧查询失效，避免晚到的结果覆盖当前列表。

没有同意说明时不创建 SDK 客户端。拒绝权限、跳过、超时、关闭弹窗或应用进入后台时不会继续等待定位。用户可在“设置 → 定位服务与隐私”撤回同意。

高德国内结果通常为 GCJ-02，保存时明确标注坐标系，不对结果重复转换。旧记录没有坐标系标识时保持未知，不猜测或自动修改。

## 构建

原生 SDK 无法通过单独刷新 JS 加入旧安装包，需要重新构建 APK：

```powershell
$env:JAVA_HOME = 'D:\Env\jdk-17.0.11+9'
$env:ANDROID_HOME = 'D:\Users\admin\AppData\Local\SDK'
./scripts/build-preview-apk.ps1
```

## 排查

- 鉴权错误 7：核对高德控制台的 Android 平台 Key、PackageName 和实际 APK 签名 SHA1。
- 系统只授予大致位置时，定位精度由系统和 SDK 决定，可在系统设置中启用精确位置。
- 位置或地址获取失败时仍可不附加位置保存；有效坐标没有地址时，可选择当前位置；搜索失败可重试或不附加位置。
