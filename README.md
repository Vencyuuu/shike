# 食刻 Shikè 1.4.0

React Native + Expo SDK 58 本地饮食相册。记录每一餐。

## 安装体验

安装包：`artifacts/Shike-1.4.0-preview.apk`，约 55.2 MiB。
包名 `cn.shike.app`，版本 `1.4.0 (10)`，Android 7.0+，包含 ARM64 与 x86_64。
签名与 1.1.0 相同，可直接覆盖安装；不要先卸载，以免清除本地记录。

## 1.4.0 原片保存与导入

- 安装图标采用用户选定的 C4 摆正版；包含传统密度资源与自适应图标，适配系统圆形和圆角遮罩。
- 旧版照片一直保存在应用私有 files/shike/generation-…/media/Originals，缩略图位于 Thumbs，卸载会清除。
- 新拍摄在筛选完成时把选中原片另存到系统相册 Pictures/Shike，也可在“设置 → 拍摄原片保存目录”通过系统目录选择器指定位置；只影响以后拍摄，不移动旧文件。
- 应用继续持有独立展示副本及缩略图；原片目录不可写时明确报错并保留拍摄会话，不静默保存到别处。提交失败重试复用已写入原片，避免重复生成文件。
- Android 导入通过系统图片文档选择器取得真实 URI；从哪个日期发起就直接归入哪个日期，不再二次询问。
- 删除时可选同时删除源文件。Android 11+ 的相册原片由系统确认删除，文档来源使用原有授权；取消或失败时保留应用记录，可取消勾选后仅移除记录。
- 旧记录缺少引用时，可在单张删除弹窗点击“关联原图”，由用户重新选择同一张照片；关联后仍需勾选、确认才会删除。
- 备份恢复会清除外部源引用，防止跨设备媒体编号相同导致误删；内部照片和餐次信息不变，之后可手动关联原图。
- 云端或只读提供方可能不允许删除源文件，此时保留记录并提示，不申请全盘文件管理权限。

## 1.3.1 直接保存与圆角反馈

- 拍摄筛选页右上角“完成”直接保存照片，不再打开最终信息确认弹窗。
- 花费、评分、位置完全选填；未主动填写的字段保持为空，已经确认的内容随照片一起保存。
- 保存失败保留筛选会话和临时照片，可重试；保存期间禁用完成按钮并以锁防止重复入档。
- 共享点击组件移除 Android 的矩形原生涟漪，改用继承控件圆角的轻量底色、透明度和缩放反馈。
- 透明入口与实色按钮分别保留正确层级，胶囊、日历日期、浮动按钮无需额外裁剪容器。
- 类型检查、ESLint 与 18 项既有回归测试通过；原生长按截图断言覆盖胶囊与日历的圆角外泄漏。

## 1.3.0 附近地点与夜晚模式

- 时间轴添加按钮改为细描边胶囊；顶部返回、返回首页与删除采用更大的图标和文字。
- 花费、评分、位置三个入口并排显示；详情仍在图片底部蒙层编辑，外部时间轴保持所有图片网格。
- 位置打开地点选择弹窗，显示附近地点名称、地址及距离，可搜索、重新定位、不附加或选中后确认。
- 高德定位 SDK 6.5.1 搭配搜索 SDK 9.7.0；选中商户保存其地点坐标，而非用户站立位置。
- 增加跟随系统、日间、夜晚三种外观并记住选择；弹窗、列表及导航随主题变化。
- 地点搜索与定位共用 Android Key；更新位置服务同意说明，旧同意需重新确认后才使用新服务。
- 类型检查、ESLint、18 项回归测试通过。最终 APK 在 Android 15 模拟器以测试坐标实测高德附近地点及关键词搜索、选择保存、重启保留、系统主题跟随和小屏弹窗。
- 原生界面断言：scripts/debug/check-places-ui.cjs；验证记录：artifacts/validation/1.3.0/。

## 1.2.1 高德定位

- Android 附加位置改为高德原生定位 SDK 6.5.1，使用固定依赖与 React Native Kotlin 桥接。
- Key 位于 `android/gradle.properties` 的 `AMAP_API_KEY`，支持同名环境变量覆盖；包名与 APK 签名保持不变。
- 用户主动附加位置并同意说明、授予系统前台权限后才创建 SDK 客户端；系统权限与开关检查不依赖 Google 定位接口。
- 高精度单次定位，禁用位置缓存；缺少地址时通过同一 SDK 补充逆地理信息，失败则保留有效坐标。
- 成功、失败、超时、跳过、关闭弹窗及离开前台均释放 SDK 客户端。设置页可查看高德隐私说明并撤回同意。
- 新位置保留高德来源及坐标系（国内一般为 GCJ-02）；旧位置不自动转换或猜测坐标系。
- 照片、花费和评分保存在本机；使用高德定位时，必要的位置、设备及网络信息由高德处理，用于定位与地址解析。
- 接入说明：`docs/高德定位接入说明.md`；14 项领域与备份回归测试通过。
- Android 模拟器使用测试坐标实际调用高德 SDK，中文地址回填、取消、拒绝、撤回后重新询问和重启保留均已验证。

## 1.2.0 餐次信息

- 外部时间轴保持图片网格，只有详情内按时间、餐次分组；每次拍摄与每批相册导入形成独立组。
- 图片详情底部使用可展开 / 收起的文本蒙层，展示该组地点、花费与评分，可随时编辑。
- 花费以人民币整数分存储；五星支持点击和滑动半星，可不评分，也可清除评分。
- 拍摄筛选页提供“花费”“评个分吧”，最终完成时可选择附加当前位置，所有信息均可留空。
- 仅主动选择附加位置时申请前台权限；不使用后台定位，不用旧地点冒充当前位置。地点名称支持手动补充。
- 定位失败、拒绝权限或取消定位均不影响保存照片；位置、花费与评分只存于本地及用户导出的备份。
- 数据库通过事务迁移至 v2，升级前自动备份；旧照片按日期保留为历史组，不猜测原餐次。支持恢复 v1、v2 备份。
- 11 项领域与真实 SQLite 回归测试通过，覆盖金额精度、半星评分、分组排序、迁移和含餐次信息的备份恢复。
- Android 模拟器验证旧版覆盖升级、滑动半星、清除评分、不同地点独立保存、重启保留、拒绝定位及全部留空保存；定位使用模拟坐标。

## 旧记录处理

1.2.0 数据库通过事务升级至版本 2，没有清库、重建或删除旧记录；旧照片归入可编辑的历史组。

- 原图还在、缩略图缺失：重新生成缩略图。
- 仅缩略图还在：保留现有画面恢复原图副本，并提示清晰度可能降低。
- 两份副本均缺失：保留记录，点击照片格重新选择原图；保留原记录的 ID、日期、时间和排序。

旧版已经删除且没有任何其他副本的照片无法自动找回。如果系统相册原图仍在，可以重新选择修复。
修复过程不在启动时申请额外相册权限。

## 开发与构建

需要 Node.js、JDK 17、Android SDK；依赖版本由 `package-lock.json` 锁定。

```powershell
npm ci
npm start
npm run android
npm run typecheck
npm run lint
npm test
```

业务源码已经从本机构建缓存恢复为可编辑的 ES Module / JSX，新增图片组件采用 TypeScript。
`index.ts` 正常注册真实应用。正式 APK 直接通过 Gradle 从源码生成，不再使用旧字节码复用规则。

```powershell
powershell -ExecutionPolicy Bypass -File scripts/build-preview-apk.ps1
```

Windows 本机使用 `.expo/tools/gradle-9.4.1/` 和 `.expo/ninja/ninja.exe`。
独立项目缓存用于避开编辑器 Gradle 导入锁；新版 Ninja 用于解决 Windows 长路径限制。
iOS 原生编译需要 macOS / Xcode，本次没有执行 iOS 验收。

## 关键位置

- `src/components/MeasuredPhotoGrid.tsx`：实测网格尺寸。
- `src/components/LocalPhoto.tsx`：本地图片与加载失败提示。
- `src/components/CaptureScreen.js`：拍摄、筛选、预览与选择状态。
- `src/components/PhotoViewer.js`：明确视口尺寸的大图查看器。
- `src/data/media-write.js`：异步副本提交屏障。
- `src/data/repository.js`：数据写入、旧记录修复和备份恢复。
- `regression/`：复制竞态、失败处理与归档格式测试。
- `scripts/debug/`：仅允许操作模拟器的反馈工具，不用于交付打包。
- `scripts/recovery/`：缓存灾难恢复工具，默认拒绝覆盖已经存在的源码。
